# 本地 Web 邮件阅读

Web 正文读取本地数据库；已读／未读操作会连接邮箱服务器同步状态，回复窗口中点击「发送」会通过邮件所属账户发送邮件。

## 打开指定邮件

```sh
jianxin -a 862945626@163.com list
jianxin open <邮件ID>
```

`open` 会启动临时本地服务，并在默认浏览器打开指定邮件。完整邮件 ID 可跨账号查找；前缀不唯一时，用 `-a <邮箱>` 限定账号。

只获取阅读网址、不打开浏览器：

```sh
jianxin open <邮件ID> --no-open
```

每次 `open` 的临时服务使用随机端口，30 分钟没有请求后自动退出。首页直接使用 `http://127.0.0.1:<端口>/`，不附加随机路径。服务仅允许本机访问。

## 持续运行 Web 阅读端

```sh
jianxin web
jianxin web --port 8788
jianxin web --message <邮件ID> --open
```

命令输出完整网址。手动打开它即可进入基于 Timeless / jxui 的邮件工作区：
浅灰邮箱侧栏、对话列表和右侧阅读面板。侧栏常驻多个邮箱及各自的 Inbox 等文件夹，支持独立折叠。邮箱状态复用 TUI 的最后同步记录，每 5 秒读取一次；状态刷新不触发远端同步。可切换账号与文件夹，筛选未读，
按主题、发件人和摘要关键词搜索。列表每页 50 条对话，相同 thread id 聚合为一条，
徽章显示邮件数；打开对话后按时间正序展示首封邮件及后续回复，超过 50 封可继续加载。
同一邮件在 Gmail 收件箱、所有邮件等文件夹中的副本只显示一次，优先显示收件箱副本；不同 Message-ID 的真实邮件仍分别显示。
窄屏使用单栏阅读，点击「返回列表」切回列表；浏览器前进和后退恢复所选对话及筛选。

左侧「全部邮件」「未读邮件」均显示所有已配置邮箱的本地邮件总数（含 0），
按 TUI 的规则去除同一邮箱不同文件夹中的邮件副本，排除已删除邮件。
总数不受当前搜索、文件夹或分页影响，每 5 秒随邮箱状态刷新，已读同步后也会刷新。

「未读邮件」下方的「收藏」汇总所有已配置邮箱的收藏邮件，沿用对话列表、搜索和分页。
阅读邮件时点击「收藏／取消收藏」，立即更新按钮状态和收藏数量，同时同步邮箱服务器的星标；失败时回滚状态和数量并可重试。同步期间的后台刷新保留乐观状态，写入完成后静默刷新列表。

邮箱名称左侧显示离线打包的平台 SVG favicon。每个账户可配置 `"platform": "qq"`，
支持 `gmail`、`outlook`、`qq`、`foxmail`、`163`、`126`、`yeah`、`aliyun`、`sina`、
`139`、`icloud`、`zoho`、`yahoo`、`fastmail`、`proton`、`tencent`（腾讯企业邮）。
未配置时按 `provider` 判断：`google` 使用 Gmail，`microsoft` 使用 Outlook，
`generic-imap` 使用通用邮箱图标；`platform` 只控制外观，不改变邮箱连接方式。
邮件列表中的收件邮箱左侧也显示同一平台 favicon，修改配置并刷新后同步更新。
正常同步不显示状态文字；未同步、等待授权、缺少凭据、登录或同步失败时，
图标上显示异常角标。点击角标查看具体状态提示，再次点击、点击外部或按 Escape 关闭；
恢复正常后角标和提示自动消失。提示使用已有的脱敏状态，不展示原始凭据或错误堆栈。

“等待 OAuth 登录”的提示提供“开始 OAuth 登录”按钮，复用 CLI 的 Device Code 流程。
点击后显示授权码和“打开授权页面”入口；在服务商页面输入授权码并完成登录。
授权成功后自动保存 refresh token、刷新邮箱配置，并重启原本已运行的后台收信服务。
前端仅显示授权码、HTTPS 授权链接及脱敏状态，不接收 access token、refresh token 或 device code。
重复点击不会启动多个授权；拒绝、过期、配置或凭据保存失败会显示提示并允许重试。
账号的 `auth` 必须配置 `type: oauth2`、`client_id` 和支持 Device Code 流程的 `token_endpoint`。
Outlook 的流程见 [Microsoft 官方设备授权说明](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-device-code)。

右上角通知中心记录邮箱状态更新、邮件加载和已读同步错误，显示未读数量。
可将单条通知标为已读或未读，也可全部已读；打开面板不会自动标为已读。
重复错误合并计数，最多保留 100 条。记录保存在当前浏览器来源的本地存储；
服务换用其他端口后，浏览器来源不同，历史不共享。

在地址后追加 `/components` 可查看 design + jxui 组件示例。
前端源码、视觉契约和构建方法见 [webpc/README.md](../webpc/README.md)。
刷新按钮读取本地数据，不会强制进行远端同步。

修改 `config.json` 的邮箱配置后，点击侧栏下方的「刷新邮箱配置」，即可更新账户列表、服务器端点和凭据，无需重启 Web 服务。同时重启使用这份配置的后台收信服务，让它读取新凭据并立即开始新一轮同步；原本未运行的后台服务不会自动启动。侧栏显示重启结果，邮箱状态随后台同步结果每 5 秒更新。配置无效时保留当前账户，有邮件状态写入或助手任务正在执行时请稍后重试。`general` 的 Web 设置仍需重启 Web 服务才能生效。

外部本机程序可调用 `POST http://127.0.0.1:<端口>/api/notifications` 发送系统通知，
`Authorization: Bearer` 请求头必须携带 `general.api.token` 中的 token。参数和认证方式见 [HTTP notification hook](desktop-notifications.md#http-notification-hook)。
持续接收推送时使用 `--idle-seconds 0` 保持 Web 服务运行。

终端按 `Ctrl-C` 停止服务。后台同步产生新邮件后，刷新列表页即可看到。

服务只监听 `127.0.0.1`，不开放局域网访问。端口被占用时可更换端口或用 `--port 0` 自动分配。`--idle-seconds N` 可以指定空闲退出时间，默认 `0` 持续运行。

## 添加邮箱

点击侧栏的「添加邮箱」，选择一种方式：

- **密文文件**：读取本地加密配置并在浏览器解密。
- **HTTPS URL**：下载加密配置，再在浏览器解密。
- **手动添加**：选择 QQ、163、126、Gmail、Outlook、阿里云或「其他邮箱」，填写邮箱地址、显示名称与密码 / 客户端授权码。

手动添加沿用 Android 的服务商选择与高级设置流程。服务商会自动填入 IMAP / SMTP 服务器；「高级设置」可修改登录用户名、服务器、端口、TLS / STARTTLS，以及 OAuth 应用设置。「其他邮箱」默认展开高级设置。QQ、163 等需要先开启 IMAP / SMTP 并使用客户端授权码。

点击「验证并预览」会验证 IMAP 连接与凭据，展示要添加或更新的账号；确认后点击「保存所选邮箱」。验证失败不会保存配置。Outlook 可以不填密码，先保存待授权账号，再点击邮箱状态图标补充 Client ID 并完成 OAuth 登录。预览不会发送邮件，SMTP 设置在实际发信时验证。

三种方式共用账号预览和保存流程。已有账号会显示「更新」提示，只保存勾选的账号，并保留其他账号、桌面设置和数据目录。保存后刷新邮箱列表，并通知已运行的后台收信服务加载新配置。关闭弹窗、切换添加方式或保存成功后会清除表单中的凭据；手动填写的账号凭据按现有配置机制保存在本机配置文件中。

## 同步日志

点击侧栏「同步日志」，查看每个邮箱的当前状态、最近同步时间和历史结果。支持按邮箱筛选、分页和手动刷新；第一页每 5 秒自动更新。时间按当前设备的本地时区显示。

CLI 同步、后台自动收信、TUI 收信和 Agent 同步结束后都会记录结果；登录或连接失败同样记录。日志只保存安全的结果分类，不保存密码、令牌、邮件内容或服务器原始错误。每个邮箱保留最近 1000 条，保存在本机邮件数据库中，重启后仍可查看。

日志从升级后的首次同步开始记录，旧的状态文件无法还原历史时间。桌面托盘的「邮箱」二级菜单会列出所有已配置邮箱及最近同步时间、当前状态，点击邮箱打开对应的邮件列表。

## TUI

展开对话并选中一封邮件后，按 `b` 在浏览器阅读。保持 TUI 可继续操作；HTML 页与 TUI 使用相同配置和本地邮件数据库。

## 已读／未读

- 单封邮件在可见页面加载正文后自动标为已读；GET 页面请求本身不会修改状态。
- 对话页默认只展开首封邮件。后续回复展开并加载正文后才上报已读，未展开的邮件保持原状态。
- 每封邮件旁有「标为已读／标为未读」按钮，显示同步中的提示以及同步结果。
- 先同步邮箱服务器，成功后更新本地标记、文件夹和对话未读数量，TUI 会读取数据库变化自动刷新。
- 网络或授权失败时原状态不变，页面提示重试；不会把失败操作显示为已成功。
- 手动标为未读后，该页面不会立即自动改回已读；重新打开阅读页会重新触发自动已读。

## 邮件元数据与发件人详情

文件夹视图只展示该文件夹内的邮件；发件人、摘要、时间、数量、搜索和分页也按该范围计算。
收件箱中的往来对话不会因自己发送回复而改成显示自己的发件摘要；已发送回复在「已发送」中查看，「全部邮件」保留完整对话。

邮件头右侧「更多」菜单中的「邮件元数据」通过弹窗查看本地 `id`、`threadid`、邮件头 `Message-ID`、
服务器 `remote_id`（IMAP UID）、所属邮箱与文件夹 ID、对话关联字段及收发时间。
字段文本可以直接选中复制。`id` 标识本地记录，`threadid` 标识对话，`Message-ID` 用于核对邮件身份。
发件人姓名旁直接显示邮箱地址；点击姓名或「发送至」，可查看完整的发件人、收件人、抄送和 Reply-To（如有）；这些操作只读取本地数据，不修改已读状态。
点击「关闭」或按 Escape 可收起详情，元数据弹窗也可点击遮罩关闭。

## 回复邮件

邮件头右侧或正文底部点击「回复」，打开独立悬浮窗口。可拖动标题栏移动窗口，桌面端可拖动窗口右下角调整大小；
标题栏获得焦点后也可用方向键移动。切换邮件或返回列表时，回复窗口及内容保留。
确认发件账户，编辑收件人、抄送和正文后点击「发送」。主题自动继承原主题并加上 `Re:`（已有时不重复添加），显示于窗口标题；通过「修改主题」展开主题编辑。标题栏支持最小化和放大，草稿内容保留。
优先使用原邮件的 Reply-To，未提供时使用 From；回复自己发出的邮件时使用原收件人。
收件人和抄送可按姓名或邮箱搜索，从已配置邮箱的本地邮件往来中选择；不会调用远端通讯录。
可移除已选地址，或直接输入邮箱地址，按 Enter / Tab / 逗号添加；支持逗号分隔的多个邮箱地址。
收件人和抄送合计最多 100 人。下拉结果支持方向键选择和 Enter 确认。
点击附件按钮选择文件，或将文件拖入回复窗口；可在发送前移除附件。
附件最多 20 个、合计 20 MB，读取完成后随邮件发送；具体邮箱服务器可能有更低限制。
发送使用邮件所属账户，与侧栏当前选择无关。自动添加配置中的签名和 In-Reply-To / References，
已发送的本地副本归入对话。正文目前使用纯文本。

发送前先写入持久化 outbox。失败或网络断开时保留编辑内容，不自动再次发送；
先核对已发送邮件和 `jianxin -a <邮箱> outbox`；确认未投递后，失败任务先用
`jianxin -a <邮箱> outbox --retry` 移回队列，再用 `jianxin -a <邮箱> outbox --flush` 投递。
关闭未发送的窗口需要确认丢弃；刷新或离开网页时提示未发送内容，内容不跨页面刷新保存。

## 正文安全与限制

- 默认使用 HTML 正文，无 HTML 时显示纯文本；可以切换视图。
- 邮件正文自动随内容和图片加载调整高度，使用整页滚动，不提供正文内滚动条。
- 邮件经过 HTML 安全清理，在无脚本权限的 sandbox iframe 中渲染，脚本、表单、嵌入网页和自动跳转被禁用。
- 默认加载 HTTPS 远程图片，HTTP 图片由浏览器自动升级为 HTTPS，升级失败时不回退 HTTP；发件人可能通过图片获知阅读行为。点击「屏蔽远程图片」可关闭加载，此选择保留在当前服务网址的查询参数中，并在页面内切换对话时沿用。
- 正文链接在新标签页打开，不发送本地页面的 Referer。
- 当前不提供附件下载或 `cid:` 内嵌附件图片；某些特殊样式会因安全限制无法完全还原。
- 邮件中的链接仍可能是钓鱼链接，打开前检查目标地址。

## 邮件 Agent

右上角「邮件助手」打开右侧 Agent / MCP 面板。参考 Agentic Inbox 的交互，
Agent 可以搜索本地邮件、读取完整对话、总结未读、拟定回复以及提议修改已读状态。
切换邮箱会切换独立会话；全局导航使用所有已配置邮箱。选中的对话作为引用交给 Agent，
Agent 再按需读取内容。打开面板本身不会调用模型。

在现有配置文件的 `general` 中合并以下配置，保留已有邮箱、API token 等配置：

```json
{
  "agent": {
    "base_url": "https://你的模型服务地址/v1",
    "model": "支持工具调用的模型名称",
    "api_key": { "file": "/绝对路径/模型密钥文件" },
    "timeout_secs": 60
  }
}
```

配置支持 OpenAI 兼容的 `/chat/completions`、流式响应和 function tools。
`api_key` 也支持已有的 `env` / `keychain` / `command` 引用；macOS 应用不保证继承终端环境变量，
使用密钥文件或钥匙串更适合应用启动。密钥文件只放密钥文本，并限制文件权限。
本机模型允许使用 `http://127.0.0.1:<端口>/v1` 且省略 `api_key`；远程接口要求 HTTPS 和密钥。
修改后重启 Web 服务，未配置时展示配置提示。

- 回复流式显示，工具执行记录同步显示；每次最多 5 轮模型请求、每轮最多 4 次工具调用。
- 邮件内容会发送给配置的模型服务。邮件和模型输出按不可信数据处理，Web Agent 只暴露读取和提议工具。
- 回复草稿可修改主题、正文，确认后保存到草稿箱；不提供发送工具。收件人由原邮件的 Reply-To / From 确定。
- 已读状态变更同样需要点击确认，成功后刷新邮件列表及数量。确认卡片 10 分钟后过期，可取消。
- 停止操作阻止后续工具执行与结果发布；正在等待网络数据的请求在返回数据或超时后结束，每次请求超时限制 10–120 秒。
- 聊天按邮箱保存在数据目录 `agent-chats/`，目录权限 0700、文件权限 0600，不存模型密钥。清空会话也清除该邮箱的待确认操作。
- 会话长度和邮件工具结果有上限，长内容可能被截断。错误也记录到通知中心。
- MCP 标签提供现有 `jianxin agent` stdio 接口配置，供外部 Agent 客户端使用。

Web conversations expand all loaded messages by default. Once their bodies load in a visible reader, read flags are written back to the mailbox and local database. Read/unread updates and the following list refresh run silently; failed writes remain visible and retryable. Writes are queued so opening multiple messages does not exceed the server write limit.
